- **SQL 语句路由 (Routing):**

**Q: 如何准确判断 SQL 语句应发送给 MySQL 计算引擎还是 DuckDB 计算引擎？**

**A : 采用SQL Hint 机制显式指定执行引擎。**

- 在 SQL 语句中添加特定注释提示 /\*+ duck_execute() \*/。
- 系统解析到此 Hint，则将 SQL 路由至 DuckDB 计算引擎；否则，默认路由至 MySQL 计算引擎。

- **数据转换与映射：**

**Q: 如何做数据转换与映射 ？**

- **列式到行式数据转换**: DuckDB 计算引擎以高效的列格式 (Columnar Format)返回数据。该格式需要转换为标准的行格式 (Row Format) ，才能适配 MySQL 协议返回给客户端。
- **数据类型映射:** 需要支持 DuckDB 内部数据类型到MySQL内部数据类型的转换。

**A: 实现专门的结果集转换层 。**

- 负责将 DuckDB计算引擎返回的列式结果集高效地解析和重构为 MySQL 行格式数据。
- 该层包含类型转换逻辑，确保 DuckDB 数据类型能正确映射并表示为对应的 MySQL 数据类型。

### SQL路由机制

当系统通过 MySQL 协议层接收到客户端的 SQL 请求后，路由流程如下：

- **SQL 预处理与 Hint 检测:**

- 系统对原始 SQL 进行初步处理（如解析 Token）。
- 通过高效匹配（例如正则表达式或精确字符串查找）检测 SQL 中是否包含显式的 /\*+ duck_execute() \*/Hint。

- **执行引擎判定:**

- 检测到 Hint：将 SQL 语句标记为需由 DuckDB 计算引擎 执行。
- 未检测到 Hint：将 SQL 语句标记为需由 MySQL 计算引擎 执行（默认行为）。

- **SQL 净化:**

- 无论最终路由去向何处，都动态移除 原始 SQL 中的 /\*+ duck_execute() \*/Hint（如果存在）。移除后的 "纯净" SQL 将传递给选定的计算引擎执行。

### 数据格式转换

DuckDB 计算引擎返回的列式数据需要转换为 MySQL 协议要求的行式数据格式：

- **元数据转换**： 将 DuckDB 的列信息（列名、数据类型、长度等）转换为 MySQL ResultSet 元数据

- 处理类型映射关系，确保数据类型在两个系统间正确对应

- **数据重组**：

DuckDB 列式存储：

Column A: \[1, 2, 3, 4\]

Column B: \['a', 'b', 'c', 'd'\]

转换为 MySQL 行式：

Row 1: \[1, 'a'\]

Row 2: \[2, 'b'\]

Row 3: \[3, 'c'\]

Row 4: \[4, 'd'\]

- **内存优化**：
- 采用流式处理方式，避免大结果集占用过多内存
- 实现分批次数据转换，支持结果集分页返回

### 数据类型转换

根据不同的数据类型，如int， varchar，char, decimal， float，date等分别根据MySQL协议重新进行编码。
